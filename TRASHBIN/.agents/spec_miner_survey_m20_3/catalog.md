## Executive Summary & Library Architecture
The TradingView library bundled in this repository is **TT v29.6.0 Standalone**, an enterprise release of the Trading Terminal featuring full native broker execution, DOM, multi-chart layouts, watchlists, drawing engines, and extensive indicators.
- **Central Feature Manager**: Module `440891` (located in bundle `2614.3c6e9a4d2c016c8e0d98.js`), exporting `{ enabled, enable, disable, getAllFeatures, setEnabled }`.
- **Inheritance Engine**: Featuresets support subset hierarchy via `o[feature].subsets`. When a parent featureset (e.g. `trading_terminal` or `charting_library_base`) is enabled, all descendant subsets automatically inherit an enabled state unless explicitly disabled in `disabled_features`.
- **Broker Adapter Core**: Handled in `trading.5355aa53ba59846168ee.js` and `trading-groups.9659877d7d96e0bb027b.js`. ConfigFlags govern all UI controls (brackets, preview lines, position netting, leverage, close buttons). Default flags are registered in internal object `Ie` (82 flags), with 8 additional dynamic flags probed in bundle code, making **90 total supported broker configuration flags**.

## Edge Cases
The following table details edge case behaviors, parameter boundaries, and conflict resolutions observed in the bundle code:

| # | Feature | Input | Observed Behavior |
|---|---------|-------|-------------------|
| 1 | `trading_terminal vs charting_library` | Both enabled simultaneously | trading_terminal supersedes charting_library, loading full Account Manager dock, DOM widget, and multi-chart layouts. |
| 2 | `order_panel without broker_factory` | order_panel enabled, broker_factory undefined | Order panel UI renders in disabled state; buy/sell buttons show 'No broker connected' message. |
| 3 | `supportPlaceOrderPreview with missing createPlaceOrderContext` | supportPlaceOrderPreview: true, broker has no createPlaceOrderContext | TradingView logs warning and falls back to internal pre-order stub; dragging line fails to update custom broker ticket if context is unlinked. |
| 4 | `supportBrackets (legacy flag)` | brokerConfig.configFlags.supportBrackets: true | Automatically patched by patchConfig() in trading.5355aa53ba59846168ee.js: mapped to supportOrderBrackets and supportPositionBrackets, emitting deprecation warning. |
| 5 | `supportModifyOrder (legacy flag)` | brokerConfig.configFlags.supportModifyOrder: true | Automatically patched to supportModifyOrderPrice, supportEditAmount, and supportModifyBrackets. |
| 6 | `seconds_resolution without UDF support` | seconds_resolution enabled, datafeed supports_seconds: false | Resolution picker displays seconds, but selecting interval triggers datafeed resolution error or empty chart. |
| 7 | `14851, 38914, atsv2s (Telemetry features)` | 14851 enabled | Triggers internal GA/telemetry sampling if Math.random() <= 0.02. Harmless when offline or blocked. |
| 8 | `hide_left_toolbar_by_default vs left_toolbar` | Both enabled | Left toolbar is compiled and mounted to DOM, but initialized in collapsed/hidden state until toggled. |
| 9 | `allow_supported_resolutions_set_only` | Enabled with custom_resolutions | Strictly disables the custom resolution '+' button, overriding custom_resolutions. |
| 10 | `fix_left_edge on high-frequency 1S chart` | fix_left_edge enabled | Prevents infinite scroll past initial loaded history candle; stops datafeed from firing unnecessary back-history requests. |
| 11 | `use_localstorage_for_settings with custom save_load_adapter` | Both active | Settings adapter syncs with LocalStorage for visual preferences while chart layouts route to custom save_load_adapter. |
| 12 | `supportClosePosition vs supportPartialClosePosition` | supportClosePosition: true, supportPartialClosePosition: false | Position close 'x' closes entire lot size; partial quantity input is suppressed. |
| 13 | `supportRiskControlsAndInfo` | supportRiskControlsAndInfo: false | Hides pips and percentage risk calculations on bracket drag handles; shows money amount only. |
| 14 | `iframe_loading_same_origin` | Enabled in standalone widget constructor | Renders iframe via URL.createObjectURL(new Blob(...)) eliminating cross-origin script latency and enabling direct window access. |

## Interactive Draggable Order Line Architecture
Milestone M20 requires rendering the native interactive draggable Limit and Stop order placement lines on chart canvas when Limit/Stop order type is selected in the order panel.

### Key Architectural Components Mined in JS Bundles:
1. **`PreOrderItem` & `LineToolOrder`** (Bundle `6161.10c4a7de17f463d1d76e.js`):
   - `LineToolOrder` manages the rendering of order lines on the chart pane.
   - When an order is not yet placed, it is represented as a `PreOrderItem` (id: `n.preOrderItemId`).
   - It renders horizontal dashed/dotted line (`lineStyle: LineStyle.Dotted`), price pill on price scale, quantity badge, and attached SL/TP projection brackets (`ProjectionBracketItem`).
   - Dragging the handle triggers `onMove(e)` -> `applyPriceDiff(diff)` -> recalculates price via `priceScale().coordinateToPrice(y)` and notifies the order panel.
2. **Traded Context Linking (`_tradedContextLinking`)** (Bundle `trading-groups.9659877d7d96e0bb027b.js` and `trading.5355aa53ba59846168ee.js`):
   - Connects the order ticket/panel view model to the chart pane.
   - Call sequence: When user selects 'Limit' in ticket -> `broker.createPlaceOrderContext({ order, source, signal })` is called.
   - Resulting context is registered via `_tradedContextLinking.setContext(context)`.
   - This links the active pre-order to the chart pane, spawning the interactive line immediately.
3. **Mandatory Configuration Flags Required**:
   - `supportPlaceOrderPreview: true` (enables place order line preview)
   - `supportModifyOrderPreview: true` (enables modify order drag preview)
   - `supportOrderBrackets: true` (enables TP/SL bracket handles on order line)
   - `supportPositionBrackets: true` (enables TP/SL bracket handles on position lines)
   - `supportRiskControlsAndInfo: true` (enables dollar/pip risk calculations on drag handles)
4. **Mandatory Chart Properties Required**:
   - `tradingProperties.showOrders = true` (Chart Settings -> Trading -> Orders must be true)
   - `tradingProperties.showPositions = true` (Chart Settings -> Trading -> Positions must be true)
   - `tradingProperties.showBrackets = true` (Chart Settings -> Trading -> Brackets must be true)
5. **Mandatory Broker Adapter Methods**:
   - `createPlaceOrderContext(options)`: returns place order context with `.setPrice()`, `.setQty()`, `.send()`, `.destroy()`.
   - `createEditOrderContext(options)`: returns edit order context for working order modification.
   - `getOrderDialogOptions(symbol)`: returns allowed durations, order types, and bracket parameters.
   - `getPositionDialogOptions(symbol)`: returns allowed position modification options.
   - `getSymbolSpecificTradingOptions(symbol)`: returns per-symbol bracket limits and min/max ticks.
   - `formatter(symbol, isSpread)`: returns custom price formatter conforming to symbol minTick.
